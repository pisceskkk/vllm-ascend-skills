# 验收与迭代

分别验收：

| 类别 | 需要证据 | 不足以证明通过 |
|---|---|---|
| 语义正确 | 同输入/配置比较及边界验证 | 服务启动、一次请求成功 |
| 调度正确 | 源码映射、依赖、资源交叠、等待和生命周期 | 两个 stream 的矩形相交 |
| 性能改善 | 无 profiler 的重复配对实验 | 重叠率提升、单次时延降低 |

整数/索引/slot 等语义通常要求一致；浮点、token 或任务指标选择与改动相符的判据，容差有依据。已知随机性先测 baseline 自身稳定性；不能用宽松平均指标掩盖 race。

行为检查：确认算子身份与内部展开；确认输入 ready 和 event 顺序；比较同 shape/dtype/layout/tiling 的 kernel 膨胀；量化双方覆盖率、launch skew、等待、局部 wall-time 与 step wall-time；检查等待是否移至消费者、在途 tensor 是否增加；覆盖空输入、尾块、rank 角色及 graph replay。

有意义的回归用例：共享 view 的异步读写；投影前的向量转换影响掩盖；一目标多伙伴的并集统计；大 epoch 下亚微秒精度；跨 phase/rank 错配；低 batch 下同步开销；源码漂移导致映射失效。

性能测量预热后交替 baseline/candidate，保存每轮而非只取最好值。区分稳态、编译、负载失败和基础设施故障。根据预设目标权衡 throughput、TTFT、ITL 与尾延迟。profiler 扰动明显时降低开销或重复短窗口，最终收益以关闭 profiler 为准。

- keep：正确性、目标行为和性能门槛通过，必测组合满足回归预算。
- revise：依赖合理但前置工作、launch、同步、核资源或带宽限制收益，明确下一轮修改因素。
- reject：可重复错误或回归，保留证据并回退本轮自己的改动。
- unresolved：证据/能力不足，明确待补项，不标通过。

按新变化、失败与未解决问题扩大测试。固化代码、配置/输入 hash、软硬件、采集位置、分析命令、源码映射、DAG/配对和逐轮测量。提交/推送遵循任务授权。
